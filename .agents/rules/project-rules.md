# 项目定位
你正在协助开发 `smart-cs-agent`（企业智能售后与工单分流 Agent）。目标是一个可上线部署、代码清晰、经得起技术面试逐行追问的轻量级 Python 后端工程，而不是堆砌概念的复杂框架演示。

# 技术栈红线（严格遵守）
1. **后端**：Python 3.11+、FastAPI、Pydantic v2、Uvicorn。
2. **数据库**：使用 Python 标准库 `sqlite3` + 原生 SQL（参数化查询防注入），**禁止引入 SQLAlchemy / Tortoise 等重型 ORM**，保证数据操作透明易读。
3. **大模型调用**：使用官方 `openai` Python SDK，通过 `.env` 配置 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL_NAME`，保证可无缝切换国内大模型（DeepSeek/通义/豆包等）。**禁止引入 LangChain、LlamaIndex 等重型编排框架**。
4. **向量检索（第 3 周再用）**：ChromaDB 轻量本地持久化。
5. **前端（第 5 周再用）**：仅用 Streamlit 或飞书 Webhook，**禁止生成 Vue / React / 前端构建工程**。

# 代码质量约束
1. **小步拆分**：按 `routers/`、`services/`、`db/`、`schemas/` 分层，单个 `.py` 文件尽量不超过 200 行，禁止把所有逻辑塞进 `main.py`。
2. **类型与校验**：所有接口入参、出参必须用 Pydantic Model 严格定义；所有核心函数必须带类型注解（Type Hints）。
3. **中文注释**：核心函数、SQL 语句、异常处理和工具调用逻辑必须写简明中文注释，重点解释“为什么这么处理边界情况”。
4. **错误处理与日志**：禁止静默 `except: pass`。外部 API 调用和数据库写入必须有明确的异常捕获、超时控制和结构化日志输出。

# 协作与安全纪律
1. **先给方案再改代码**：每次修改涉及 2 个以上文件或结构变动时，先列出简短计划（改哪些文件、做什么），等我确认后再动手。
2. **禁止越权操作**：执行安装依赖、删文件、重置数据库等终端命令前，必须先征求我同意。
3. **严禁泄露密钥**：永远不要把真实 API Key 写进任何代码文件；新建配置项时同步更新 `.env.example`。
4. **单次任务最小化**：只完成我当前指定的这一个模块，不要“顺手”提前实现后面几周的功能（比如第一周不要自己加 RAG 或前端）。
5. **代码讲解机制**：每次写完核心代码后，用 3–5 句大白话告诉我：① 新增/改了哪几个文件；② 核心数据流是怎么走的；③ 怎么本地运行和验证。
